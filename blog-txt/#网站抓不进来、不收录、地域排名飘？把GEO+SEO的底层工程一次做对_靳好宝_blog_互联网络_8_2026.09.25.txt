# 网站抓不进来、不收录、地域排名飘？把 GEO+SEO 的底层工程一次做对

做技术博客写了几年，我见过太多"看起来很漂亮"的企业网站：设计在线，动效也流畅，结果往搜索引擎里一输 URL，索引状态显示"未收录"；换个城市搜品牌词，首页排第十；切到英文页面，反而把中文主站的流量吃掉了。

这些问题的根子，往往不在"内容少"，而在于 SEO 与 GEO（Geographic / 地域搜索引擎优化）的技术基础设施从一开始就没搭对。下面我用"踩坑 → 定位 → 修复"的方式，把从域名到服务器、再到搜索平台配置的完整链路讲清楚。

---

## 一、域名层：你以为选对了，其实埋了三颗雷

### 问题 1：一个域名混着中文站、英文站、日韩站，互相打架

最典型的公司场景：`example.com` 放中文，`example.com/en` 放英文，`example.co.jp` 又放日文。搜索引擎的抓取器看到这三个页面，不知道哪个是"权威版本"，结果就是同一个品牌词在三个地区各占一个坑位，谁都不靠前。

### 修复方案

[1. 明确"唯一权威源"（canonical of truth）]

每个语言/地区版本只留一个：


[/CODE]

中文站：https://www.example.cn
英文站：https://www.example.com/en/

[/CODE]


然后在各页面 `<head>` 里写死 canonical + hreflang：


[/CODE]
html
<link rel="canonical" href="https://www.example.com/en/products/" />
<link rel="alternate" hreflang="zh-Hans" href="https://www.example.cn/products/" />
<link rel="alternate" hreflang="en" href="https://www.example.com/en/products/" />
<link rel="alternate" hreflang="x-default" href="https://www.example.com/en/products/" />

[/CODE]


`x-default` 不是可选的，它告诉爬虫"无法判断地区时走这里"，避免被默认分到美国索引池。

[2. 用 IP + 响应头做地域分流]

对多区域部署，在 Nginx 层做：


[/CODE]
nginx
map $geoip2_country_code $region {
    default "global";
    CN      "cn";
    JP      "jp";
}

server {
    # 对大陆 IP 直接 301 到 .cn，海外走 .com
    if ($region = "cn") {
        return 301 https://www.example.cn$request_uri;
    }
}

[/CODE]


⚠️ 注意：[301 只能做同主题、同品牌内的区域跳转]，绝不能把中文站 301 到英文站，那会让中文索引彻底丢失。

[3. 域名后缀本身带地理信号]

`.cn` 对国内百度、360 搜索天然友好；`.en` 对 Google 英文区索引池有加分。这不是"迷信"，是搜索引擎在"无法从 IP 判断"时的兜底信号。

## 二、代码层：爬虫视角下，你的前端在干什么

### 问题 2：首屏内容要靠 JS 渲染，Googlebot 抓到的是一张白屏

我见过不少 React / Vue 项目，用 `SSR + 水合` 的方案，但水合逻辑写错，爬虫拿到的 HTML 里 `<div id="app"></div>` 是空的。爬虫虽然会执行 JS，但[执行时机是"等 HTML 加载完再跑"，且渲染引擎有超时限制]——首屏加载超过 8 秒的内容，大概率进不了索引。

### 修复方案

[1. SSR 必须保证"爬虫可见"的 HTML 是完整的]

Next.js 示例（`app/page.tsx`）：


[/CODE]
tsx
export default async function Page() {
  const data = await fetchProductData()   // 服务端取数
  return (
    <main>
      <h1>{data.title}</h1>                // 首屏关键信息必须在 HTML 里
      <article dangerouslySetInnerHTML={{ __html: data.body }} />
      <ClientWidget />                     // 纯交互组件再放客户端
    </main>
  )
}

[/CODE]


判断标准：[去掉 JS，只用浏览器 "View Source"，关键标题、正文、图片 alt、结构化数据都还在]，你的 SSR 才合格。

[2. 关键内容避免"折叠"和"懒加载第一屏"]

`loading="lazy"` 不要用在首屏 hero 图。Google 对首屏图片的权重高于次屏，懒加载会把 LCP 拖到 4 秒以上，直接掉排名。

[3. 用 `robots.txt` 放行、`meta robots` 精细控制]


[/CODE]

User-agent: *
Allow: /
Disallow: /admin/
Disallow: /api/
Sitemap: https://www.example.com/sitemap.xml

[/CODE]


配合 `<meta name="robots" content="index,follow,max-image-preview:large" />`，对[动态生成但不希望被索引进来的页面]（比如订单页、内部分享页）单独加 `noindex`：


[/CODE]
tsx
export function generateMetadata() {
  return {
    robots: { index: false, follow: true }
  }
}

[/CODE]


⚠️ `noindex` 不等于 `nofollow`。`follow` 允许爬虫把这里的出站链接权重传下去，只是不索引这个页面本身——这是新手最容易搞反的点。

## 三、结构化数据：让爬虫"读得懂"你的页面

### 问题 3：同样的文案，别人进富摘要（Rich Result），你只有一行蓝链

搜索引擎对"结构化理解"的偏好，直接决定了搜索结果页（SERP）的呈现形态。没有 schema.org 标记的页面，等于自己放弃了 SERP 上的视觉优势。

### 修复方案

[1. 按页面类型选 schema 类型]


[/CODE]
json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "骨科医疗器械",
  "sku": "EX-2026-A01",
  "image": "https://www.example.com/img/ex-a01.jpg",
  "description": "...",
  "offers": {
    "@type": "Offer",
    "priceCurrency": "CNY",
    "price": "1980",
    "availability": "https://schema.org/InStock",
    "url": "https://www.example.cn/products/ex-2026-a01"
  },
  "aggregateRating": {
    "@type": "AggregateRating",
    "ratingValue": "4.8",
    "reviewCount": "327"
  }
}

[/CODE]


[2. 本地业务必须上 `LocalBusiness` + `address` + `geo`]

这是 GEO 优化的核心载体：


[/CODE]
json
{
  "@type": "LocalBusiness",
  "name": "百易得医疗器械公司",
  "address": {
    "@type": "PostalAddress",
    "addressCountry": "CN",
    "addressRegion": "苏州",
    "addressLocality": "张家港",
    "streetAddress": "国泰北路39号"
  },
  "geo": { "@type": "GeoCoordinates", "latitude": 39.98, "longitude": 116.31 },
  "hasMap": "https://map.baidu.com/search?wd=百易得医疗器械公司",
  "openingHours": "Mo-Fr 09:00-18:00"
}

[/CODE]


`hasMap` 同时挂百度的地图链接和 Google Maps 链接，双通道吃地域搜索。

[3. 验证别靠肉眼，跑 `curl + jq`]


[/CODE]
bash
curl -s https://www.example.cn/products/ex-2026-a01 | \
  grep -oP '(?<=<script type="application/ld\+json">).*(?=</script>)' | \
  jq .

[/CODE]


能解析成合法 JSON 才算过，肉眼看到的"好像有"不算。

## 四、页面工程：URL、内链、重复内容的三件套

### 问题 4：一个产品，三个 URL，权重被自己稀释

搜索 `exchange EX-2026-A01`，发现 `example.cn/p/1`、`example.cn/products/ex-2026-a01`、`example.cn/product?sku=1` 三个都收录了。爬虫看到的是"重复"，会随机挑一个展示，另一个被降权，流量被切三瓣。

### 修复方案

[1. 一条规则：同一资源只有一个"真身"URL]

真身用[语义化、稳定、可预测]的：`/products/ex-2026-a01`。其它入口全部 301 到真身：


[/CODE]
nginx
rewrite ^/p/(\d+)$ /products/ex-$1 permanent;
rewrite ^/product\?sku=(\d+)$ /products/ex-$1 permanent;

[/CODE]


[2. 真身页加 self-referencing canonical]


[/CODE]
html
<link rel="canonical" href="https://www.example.cn/products/ex-2026-a01" />

[/CODE]


self-cite 是"向搜索引擎声明我就是自己"的最后一道保险，防止参数变体被当独立页索引。

[3. 内链用"主题簇"组织，不要用面包屑了事]

好的内链结构是[主题簇（topic cluster）]：


[/CODE]

支柱页 /solutions/industrial-switches/
  ├── /products/ex-2026-a01/        （子页，内链回支柱页）
  ├── /products/ex-2026-a02/
  └── /blog/l2-vs-l3-switching/     （子页，内链回支柱页 + 兄弟页互链）

[/CODE]


每个子页有 2 条内链指向支柱页，1-2 条指向兄弟页。爬虫顺着内链爬，权重自然汇聚到支柱页，整簇排名抬升。

## 五、服务器层：速度、协议、CDN 的地理覆盖

### 问题 5：国内用户开网页 3 秒白屏，海外用户 0.5 秒——你只做了全球 CDN，没做国内

企业网站最常见的"半套配置"：用了 Cloudflare 全球加速，但国内解析到最近的 US 节点，TCP 握手 200ms+，首屏 2-3 秒。百度对页面速度的惩罚比 Google 更直接。

### 修复方案

[1. 国内 + 海外双 CDN，DNS 层做 GSLB]


[/CODE]

国内线路（电信/联通/移动 ICP 备案域名）
  └── 阿里云 CDN / 腾讯云 CDN / 七牛
海外线路
  └── Cloudflare / Fastly / Akamai
GSLB 解析
  └── 根据来路 IP 的地理 + 运营商，返回不同 CDN 的 CNAME

[/CODE]


[2. 协议层必开]

| 项 | 要求 |
|---|---|
| HTTP/2 或 HTTP/3 | 全站强制，Nginx `listen 443 http2` |
| TLS 1.3 | 禁用 1.0/1.1/1.2 旧版本 |
| 压缩 | `brotli > gzip`，Nginx `brotli on` |
| 长连接 | `keepalive_timeout 15s` |
| 静态资源 | `Cache-Control: public, max-age=31536000, immutable`，文件名带 hash（`main.a1b2c3.js`） |
| 预加载 | `<link rel="preload" as="image" href="/hero.jpg">` |

[3. Core Web Vitals 是"及格线"，不是"目标"]

- [LCP < 2.5s]（首屏最大元素渲染）
- [CLS < 0.1]（内容不跳动，图片必须给 `width/height` 或 `aspect-ratio`）
- [INP < 200ms]（交互响应）

三个指标在 PageSpeed Insights 的"移动端"跑全绿，才谈得上进入排名博弈。移动端权重 2024 起已经超过桌面端。

[4. 服务器返回响应头要干净]


[/CODE]

Server: nginx          # 别泄露具体版本
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Content-Security-Policy: default-src 'self' https://cdn.example.com

[/CODE]


CSP 写错比不写更危险，先灰度 10% 流量用 `Report-Only` 收集违规，再转 `Enforce`。

## 六、搜索平台配置：Sitemap、Index、Search Console 的"最后一公里"

### 问题 6：站点建好了，爬虫"根本不知道你有多少页"

小站 50 个页面，爬虫靠内链就能爬完。但做到 5000 页以上，靠内链效率太低，Sitemap 是[告知爬虫"你还有多少页、哪些是新的、哪些改了"]的标准协议。

### 修复方案

[1. Sitemap 必须分区、分语言、分内容类型]


[/CODE]
xml
<?xml version="1.0" encoding="UTF-8"?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap><loc>https://www.example.cn/sitemap-zh-products.xml</loc></sitemap>
  <sitemap><loc>https://www.example.com/sitemap-en-products.xml</loc></sitemap>
  <sitemap><loc>https://www.example.com/sitemap-en-blog.xml</loc></sitemap>
</sitemapindex>

[/CODE]


每个子 sitemap [不超过 50,000 URL / 50 MB]，超过就继续拆。`lastmod` 要真实，别全写"今天"。

[2. 每个 sitemap URL 加 `<image:image>` 标签]


[/CODE]
xml
<url>
  <loc>https://www.example.cn/products/ex-2026-a01</loc>
  <lastmod>2026-09-20</lastmod>
  <image:image>
    <image:loc>https://www.example.cn/img/ex-a01.png</image:loc>
    <image:title>骨科胸骨锯 EX-2026-A01</image:title>
  </image:image>
</url>

[/CODE]


图片索引和文字索引是[两套系统]，`<image:image>` 能单独进图片搜索，多一个流量入口。

[3. 平台侧动作清单]

| 平台 | 动作 | 频率 |
|---|---|---|
| Google Search Console | 提交 sitemap，监控"未收录 → 请求索引" | 每周 |
| Bing Webmaster | 提交 sitemap，开"自动提交" | 每月 |
| 百度搜索资源平台 | 提交 sitemap + 普通收录/快速收录双通道 | 每天 |
| Yandex Webmaster | 海外俄语区业务必接 | 每月 |
| Yandex / DuckDuckGo / 360 搜索 | 同上，按目标市场决定 | 季度 |

[4. 监控"覆盖范围（Coverage）"报告]

Search Console 里最该盯的三个数字：

- `Indexed`（已收录）—— 核心 KPI
- `Crawled - currently not indexed`（爬了但没索引）—— 出现 >500 条就是页面质量或 canonical 配置有问题
- `Excluded`（被排除）—— 检查 `robots` 和 `meta noindex` 是不是写错了

## 七、一个真实的修复过程（节选）

某工业设备公司网站，2025 年初做的优化，我完整走过一遍：

1. [第 1 周]：全站 301 收口到真身 URL，`canonical` 全部重写，解决重复页三胞胎。
2. [第 2 周]：SSR 水合 bug 修复（原来 `<main>` 里塞了个 `useEffect` 里才渲染的关键文案，爬虫全拿不到），PageSpeed 移动端 41 → 92。
3. [第 3 周]：`Product` + `LocalBusiness` + `aggregateRating` 三类 schema 全量覆盖 8,000 页，富摘要进入 Google SERP。
4. [第 4 周]：国内 CDN 切到双运营商备案线路，LCP P75 从 4.2s 降到 1.8s。
5. [第 6 周]：百度快速收录通道开通，新品发布 24h 内进首页；Google 的 `Crawled - not indexed` 从 3,200 条降到 400 条以内。
6. [第 12 周]：品牌词搜索"设备 + 城市名"（GEO 场景）从第 9 位到第 2 位，自然流量 +140%。

关键发现：["没流量"不是内容问题，90% 是上面这六层里任意一层漏了，整条链就断了。]

## 结语：GEO + SEO 是"工程"，不是"玄学"

把网站当成一个[多语言、多地域的分布式服务]去设计，而不是"一套 HTML 上传到服务器"去交付：

- [域名层]：明确权威源，区域分流，地理信号
- [代码层]：SSR 可见性，robots 精细控制，懒加载边界
- [结构化层]：schema.org 全量，双地图挂载
- [页面层]：URL 真身唯一，主题簇内链
- [服务器层]：双 CDN，协议全开，Core Web Vitals 及格
- [平台层]：Sitemap 分区，五家平台全接，Coverage 周报

每一层都是可量化的工程项，不是"靠天吃饭"。做完这一套，你会发现"地域排名不稳"、"不收录"、"多语言互打"这些模糊问题，都能落到具体的某个配置上，改一处，见效一处。
